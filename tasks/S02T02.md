# S02T02 — Smarter, near-universal address search

**Difficulty:** hard
**Weight:** 0.4500 (share of project budget)
**Reward:** <0.001 SATS + 0.045 TON

Make the address search resolve almost any free-form query so users rarely hit a "not found".

## Acceptance criteria
- Improve geocoding so partial, misspelled, abbreviated, or loosely-formatted addresses still resolve (typo tolerance / fuzzy matching).
- Accept raw `lat,lng` coordinate input directly and short-circuit to that location.
- Add an autocomplete / suggestions dropdown as the user types, with debounced lookups.
- When the primary geocoder returns nothing, fall back to a secondary provider and/or a relaxed query (drop house number, broaden to city/region) and return the best candidate instead of failing.
- Rank multiple matches sensibly and let the user pick among the top candidates when ambiguous.
- Handle non-English (incl. Russian) place names and Cyrillic input.
- Graceful UX for the genuinely-unresolvable case (clear message, no crash); searches remain reasonably fast (debounce + caching). Build passes and existing imagery/history features still work.
